# C4.1 — Passive map-state diagnostic

Experimental branch only. The native map-open state is **not** detected by
this change. The observer records a limited set of key press edges and
manually supplied labels to support investigation.

## Launch configuration
Keep the existing local launcher and Vulkan layer manifest. Add:

```bat
set "EMBERVALE_C2_SQUARE=0"
set "EMBERVALE_C4_OBSERVE=1"
```

Restart the game after changing the environment. C4 diagnostics are disabled
by default. No GPU render operations were changed by this milestone.

## Build and stage (PowerShell)

```powershell
cmake -S . -B build-layer -DBUILD_VULKAN_LAYER=ON -DBUILD_SHROUDTOPIA_ADAPTER=OFF -DBUILD_TESTING=OFF
cmake --build build-layer --config Release --target EmbervaleCompanionVulkanLayer
Copy-Item '.\build-layer\Release\EmbervaleCompanionVulkanLayer.dll' '.\build-layer\layer-test\EmbervaleCompanionVulkanLayer.dll' -Force
```

## Test
1. Launch Enshrouded with the layer, enter the game world.
2. Open the native map with M, then press **F7** to label it visible.
3. Close the native map, press **F8** to label it hidden.
4. Try opening the map through mouse navigation in the game's interface,
   and label visible (F7), hidden (F8) again.
5. Test inventory, menus, focus loss (Alt+Tab), and return.
6. Close the game normally and inspect the log:

```powershell
Select-String -Path '.\build-layer\layer-test\embervale-vulkan-layer.log' -Pattern 'C4.1'
```

Events include `focus=0/1`, `input=M`, `input=ESC`,
`MANUAL_MAP_VISIBLE=F7` and `MANUAL_MAP_HIDDEN=F8`.
`ms` is `GetTickCount64()` monotonic Windows uptime (not wall-clock time);
`present` is the observed presentation call count.

## Interpretation and caveats

- The keyboard is polled *once per Vulkan present*. Short presses may be missed.
- Polling the Win32 key state does not prove the game consumed that input,
  nor whether its UI actually changed.
- Multiple device queues, inactive focus, non-keyboard navigation, keyboard
  remapping and other overlays can alter the observed sequence.
- F7/F8 are **manual observations**, not automatic state detection.
- `log_event` synchronously appends a line, so each logged transition may add
  latency; this is acceptable only for a local diagnostic experiment.
- No memory scanning, new hooks, or Vulkan command submission was added.
- Do not merge to master or claim the map is detected until after a Windows
  build, runtime smoke test and signal assessment.

## Next decision
Use the manual labels to assess whether a reliable in-game UI signal exists.
Do not use an M-key toggle as production map visibility. Evaluate established
Enshrouded UI/modding techniques separately before starting zoom/pan alignment.
